What it checks

Every layer of the evidence, independently

The verifier re-derives the whole chain from the raw bundle. A receipt only earns its grade if every check passes:

  • Event and manifest signatures - Ed25519 signatures over canonical records
  • Hash chain integrity - gapless sequence, unique event IDs, unbroken previous-hash links
  • Batch binding - every event provably inside the signed batch root
  • Merkle inclusion proof - bound to the exact event and signed root
  • RFC 3161 timestamp authenticity - real CMS signature verification against the Time Stamping Authority's certificate chain, checked at the moment of stamping (genTime)
  • Retention receipts - independently signed custodian proof that the evidence is retained and unaltered

Grading is cumulative and fail-closed: if any gate cannot be proven, the grade drops. The verifier under-claims; it never over-claims.

The evidence ladder

E0 to E4

GradeRequired evidence
E0No events loaded (grade-derivation API)
E1Events loaded
E2E1 plus valid event/manifest signatures, chain, sequence and signed batch binding
E3E2 plus a signed event recording provider acknowledgement
E4E3 plus bound Merkle inclusion proof, authenticated RFC 3161 timestamp and authenticated retention evidence

E4 is the top grade on the public ladder. It means a third party with zero access to the issuing operator can re-derive and confirm the whole record - including that the external timestamp itself is genuine and was valid at that moment.

Try it

Verify a bundle yourself

The verifier is offline by design. It never downloads roots, certificates or policy from a bundle - you supply the trust anchors, it does the cryptography.

# install
pip install witnessos-verifier

# verify an evidence bundle (offline)
witnessos-verifier verify ./path/to/evidence-bundle/

# authenticate E4: supply an operator trust policy + expected TSA
witnessos-verifier verify ./path/to/evidence-bundle/ \
  --trust-policy ./operator-policy.json --tsa-url https://freetsa.org/tsr

# machine-readable output for tooling
witnessos-verifier verify ./path/to/evidence-bundle/ --json

Exit 0 means the bundle verified. Exit 1 means it failed or could not be verified - an altered record cannot quietly downgrade; it is rejected.

Live since 5 Sep 2026, the WitnessOS engine issues E4-anchored receipts (real RFC 3161 timestamps, revocation-verified at issuance) under strict mode. Receipts in the full authenticated-retention format are rolling out with design partners. The verifier that checks them has been public since 9 Sep 2026.
Why it can be trusted

Attack-tested, fail-closed, auditable

Tamper suite passes15 tamper classes - altered payloads, forged proofs, corrupted timestamps, unsigned and self-signed retention receipts - all rejected at exit 1. No forged bundle reaches E4.
100 tests, hardened CI100 automated tests plus dependency scanning, DCO and real CodeQL security analysis run on every change to the public repository.
  • Secret-free by design - the verifier only ever sees public keys. No credentials, no keys, no operator secrets in the codebase.
